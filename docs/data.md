# Data: what polyT5 used, what we use instead

## 1. The problem

The polyT5 authors withheld everything:

> "The datasets generated and/or analysed during the current study are **not publicly available due to IP
> protection being considered at authors' institution."** — npj AI 2, 30 (2026), Data availability

There is no code-availability statement, no repository, no HuggingFace model, and no Zenodo deposit
(verified 2026-08-17 via the GitHub API, the HuggingFace API, and the DOI landing pages). So none of the
following exists publicly:

| polyT5 dataset | Size | Public? |
|---|---|---|
| Hypothetical pretraining polymers | 100,145,883 | ❌ |
| Experimentally synthesized polymers | 12,473 | ❌ |
| Tg (glass transition) | 5,130 | ❌ |
| Td (decomposition) | 4,204 | ❌ |
| Tm (melting) | 2,151 | ❌ |
| Eg (bandgap, DFT) | 4,113 | ❌ |
| ε (dielectric constant) | 1,569 | ❌ |
| Solubility | 29,215 cases (6,246 polymers × 58 solvents) | ❌ |

We therefore run in **substitute-data mode** and say so in every run manifest. We do **not** attempt to
recreate the authors' virtual-polymerization pipeline — the reaction SMARTS and screening rules are not
published, so any recreation would be an invention wearing the paper's name.

## 2. Data modes

`src/polyt5/data/` exposes one interface with three modes, selected in config. The mode is written into
`results/<run>/manifest.json` so no result can be misread as trained on the authors' data.

| Mode | Meaning | Status |
|---|---|---|
| `exact` | The authors' own corpus. | **Unavailable** — the loader raises with a pointer to this document. |
| `proxy` | Public, licensed substitute corpora (below). | **Default.** |
| `dev` | Tiny synthetic/sampled subset for tests and CPU bring-up. | Always available, committed-size. |

## 3. Proxy corpora we use

### 3.1 Pretraining structures — PI1M v2 *(downloaded, in repo working tree)*

- **Source**: <https://github.com/RUIMINMA1996/PI1M> → `PI1M_v2.csv`
- **Local path**: `data/external/PI1M_v2.csv` (66 MB, **995,799** polymers)
- **Format**: `SMILES,SA Score` where SMILES are star-terminated PSMILES, e.g.
  `*CCC[Fe]CCCC(=O)OCCCCOCCCNCC(*)=O`
- **License**: MIT (repository), with a README note that the data is for academic purposes
- **Provenance caveat**: generated by a model trained on ~12k PoLyInfo polymers — so it is a *learned*
  approximation of polymer space, not a reaction-enumerated one like polyT5's corpus.
- **Role**: the default pretraining corpus for Stages 1–4. Large enough to exercise the full pipeline and
  train polyT5-small/medium meaningfully on one GPU.
- **Prepared** (`data/processed/pi1m/`, tokenizer `76471956…`, max length 200 applied to real token ids):

  | | |
  |---|---|
  | Input rows | 995,799 |
  | RDKit parse failures | 7,024 |
  | SELFIES encode failures | 550 |
  | Wrong terminus count | 0 |
  | Over 200 tokens | **0** |
  | Canonical duplicates | 0 |
  | **Kept** | **988,225 (99.2%)** |

  Split 90/5/5 into 889,402 train / 49,412 val / 49,411 test. That every one of 988,225 real polymers
  fits inside 200 tokens is a useful independent check on the paper's own choice of that limit (it
  reported 99.91% coverage on its corpus).

### 3.2 Pretraining structures at scale — polyOne / polyBERT corpus *(downloaded)*

- **Source**: Zenodo record [7766806](https://zenodo.org/records/7766806) (DOI 10.5281/zenodo.7766806)
- **Local path**: `C:\Users\sumedh\polyt5-data\external\` — deliberately **outside the repository**, since
  the repo lives in a OneDrive-synced folder and 9 GB there would thrash sync indefinitely
- **Files and verified hashes**:

  | File | Bytes | SHA-256 |
  |---|---|---|
  | `generated_polymer_smiles_train.txt` | 8,144,973,512 | `289accd70e81b2c725ec090c0512a6ed67df4997c5cc13dae2a1887b6824d42f` |
  | `generated_polymer_smiles_dev.txt` | 904,631,112 | recorded in its `.provenance.json` sidecar |

- **License**: "Other (Non-Commercial)" — a Georgia Tech Research Corporation academic-use license.
  Redistribution restricted; academic use permitted. **Not redistributed here**;
  `scripts/download_data.py --dataset polyone_train --yes-large` fetches it and writes a provenance
  sidecar recording URL, byte count, and SHA-256.
- **Format**: star-terminated PSMILES, one per line, e.g.
  `[*]CCCc1cccc(-c2c(Br)cc(-c3c(Br)cc(-c4cccc(N(C)CCC[*])c4)cc3Br)cc2Br)c1`
- **Why it is the best proxy**: same research group as polyT5, same PSMILES conventions, ~100M polymers,
  already split 80M/20M. The closest public analogue of the withheld corpus, at matching scale.
- **Provenance caveat**: polyOne was generated by fragment recombination, whereas polyT5's corpus was
  enumerated from polymerization reactions over commercial monomers. Comparable coverage of polymer space,
  different generative process — recorded in every run manifest as `data_mode: proxy`.

At this scale the plain-text pipeline no longer works: the corpus is converted once into a pre-tokenized,
memory-mapped form (`corpus.bin` uint16 token ids + `corpus.idx` uint64 offsets + `corpus.json` metadata)
so that training never re-tokenizes and DataLoader workers share one page-cached mapping instead of each
holding a copy. See `src/polyt5/data/tokenized_corpus.py`.

### 3.3 Supervised Tg labels — LamaLab curated Tg *(downloaded, in repo working tree)*

- **Source**: Zenodo record [15210035](https://zenodo.org/records/15210035),
  `LAMALAB_CURATED_Tg_structured_polymerclass.csv`
- **Local path**: `data/external/LAMALAB_CURATED_Tg.csv` (5.3 MB, **7,367** rows)
- **Key columns**: `PSMILES`, `labels.Exp_Tg(K)`, plus `meta.source`, `meta.reliability`,
  `meta.polymer_class`, `meta.num_of_points`, `meta.std`, and ~110 precomputed featurizer columns we ignore
- **License**: **CC-BY-4.0** — the only permissively licensed experimental polymer Tg set we found
- **Provenance**: curated from the literature by the LamaLab group (npj Comput. Mater. 2025); programmatic
  access also available via the MIT-licensed `polymetrix` package
- **Role**: substitute for polyT5's withheld 5,130-polymer Tg set, for **both** downstream tasks (property
  prediction and Tg-conditioned generation). It is slightly *larger* than the paper's set (7,367 vs 5,130),
  which means our numbers are not directly comparable to theirs — a point we repeat in every results table.

### 3.4 Other properties (Td, Tm, Eg, ε, solubility) — deferred

Public substitutes are thinner and less consistent:

- **Khazana / Polymer Genome** (<https://khazana.gatech.edu>) — the Kuenneth multitask release
  (`MTL_Khazana.zip`, 72 KB) has 6,265 rows of **DFT-only** properties (bandgap chain/bulk, electron
  affinity, ionization energy, dielectric constant, atomization energy, …) in PSMILES form. The
  **experimental Tg/Tm/Td portion of that dataset was never released** because it derives from PoLyInfo.
  No registration required; TLS chain is incomplete, so fetch with a browser or `curl -k`.
- **polyVERSE** (<https://github.com/Ramprasad-Group/polyVERSE>) — many curated property CSVs
  (bandgap, electron affinity, permeability, conductivity, …) under a GTRC non-commercial license, but
  **no Tg dataset**.
- **PoLyInfo** (<https://polymer.nims.go.jp>) — ~7,000 homopolymers with experimental Tg, but requires
  account registration, and its terms **prohibit bulk download and redistribution**. We do not use it.

Phase 1 targets Tg only, matching the paper's own choice for the generation task. The multi-property
screening cascade (Figure 5A) is out of scope until property models beyond Tg exist.

## 4. Conversion pipeline

All corpora arrive as star-terminated PSMILES and pass through the same path:

```
raw PSMILES  ("*CCO*" or "[*]CCO[*]")
    → star_to_at            → "[At]CCO[At]"
    → RDKit parse + canonicalize + validity screen
    → selfies.encoder       → PSELFIES  "[At][C][C][O][At]"
    → tokenizer             → token ids
```

Verified locally: `selfies.encoder('[*]CC[*]')` **fails** (`EncoderError`), which is precisely why the
authors introduced the `[At]` device; `selfies.encoder('[At]CCO[At]')` succeeds and round-trips.

Rows are dropped, with counts logged, when: RDKit cannot parse them, the terminus count is not exactly 2,
SELFIES encoding fails, or the token length exceeds 200. The drop report is written to the processed
dataset's sidecar JSON so corpus attrition is never invisible.

## 5. Splits

- **Pretraining**: 90% train / 10% held out, matching the paper; the held-out 10% is further split 5% / 5%
  into validation and test (the paper does not specify this — register entry E-03).
- **Property prediction**: 80/20 train/test over **five random seeds**, matching the paper, plus a
  validation slice carved from the training portion for checkpoint selection (register entry F-01).
- **Conditional generation**: 90% train / 10% validation, matching the paper.

All splits are produced by seeded, deterministic index generation and the index lists are saved with the
processed dataset, so a split can be reproduced exactly without rerunning the pipeline.
